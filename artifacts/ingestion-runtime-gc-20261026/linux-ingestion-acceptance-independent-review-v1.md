## Options et variantes restant hors du PASS principal

1. **Déclenchement automatique et charge.** Le runner refuse explicitement Scanner/Watcher activés (`invoke-linux-ingestion.py:108`). Le template Production les active ; compose propose WorkerConcurrency2. La qualification API/enqueue à faible concurrence ne prouve donc pas les rafales filesystem, debounce, fichiers en cours de copie, scan de suppression, partage réseau, multiworker en charge ou budgets de mémoire/latence. Les tests PG prouvent des invariants de concurrence, pas un SLA runtime. Soit ces options restent désactivées dans le profil livré, soit elles reçoivent leurs propres parcours.
2. **Chemin OCR historique distinct.** Le worker conditionne cette branche à `!useDocling && ingest.OcrEnabled` (`IngestionWorker.cs:1026`). Le succès Docling ne la qualifie pas et son smoke autonome ne constitue pas un worker complet avec DocumentIntelligence désactivé, fusion natif/OCR, annulation, publication et lecture. L’image contient les outils, mais seule une exécution les exerce. Le smoke reste anglais, une page et deux lignes opérationnelles, pas une validation de toutes les langues, rotations, tableaux, négations ou scans dégradés.
3. **Reranker, GPU et autres moteurs/modèles.** Les résultats TEI natifs ne sont plus un substitut Transformers ; ils gardent cependant un modèle, tokenizer, poids ONNX et runtime exacts. Pas de qualification automatique d’un autre TEI/Docling/Qdrant, d’un modèle multilingue différent, du reranker ou d’un GPU. Les sondes synthétiques de classement et de troncature restent des témoins bornés, pas une mesure de précision/rappel métier sur toutes les questions.
4. **Figures et structures incertaines.** Les flags de figure sans interprétation ou de structure parcellaire restent visibles. Un fait annoté présent ne prouve pas la sémantique d’un graphique, l’association de chaque cellule, l’ordre de chaque bloc ni un rappel exhaustif. Un warning de grille clairsemée n’est pas automatiquement une donnée perdue : dans les deux cas synthétiques précédemment audités, la cellule absente correspondait à une annotation `empty=true`. Il faut rapprocher les warnings du PDF et de l’annotation, sans les cacher ni transformer un simple avertissement en échec certain.
5. **Pannes et reprise runtime.** Les unit/PG couvrent baux, transactions, rollback, anciennes générations et réponses incomplètes. Des crashes pendant extraction/publication, redémarrage conteneur, panne réseau intermittente des moteurs, épuisement disque, OOM et reprise de gros documents n’ont pas tous été injectés sur la pile Linux actuelle. Un job done ne prouve pas ces variantes. L’annulation HTTP n’atteste toujours pas l’arrêt du calcul Docling amont.
6. **GC historique et restauration.** Le gate réel utilise la cible courante possédée. Les autres endpoints/collections/credentials sont couverts par contrats de refus déterministes, pas par une campagne réelle multi-cible. Les points legacy sans manifeste exact restent non supprimables, pas « tous purgés ». Les plans de génération courante restent protégés. Restore/clone/reset de DB/namespace et arrêt des anciens writers exigent le protocole distinct documenté. Une référence FILE locale/petite ne prouve pas un timeout universel sur UNC/NFS.
7. **Exploitation et performances.** Les temps d’un scan ou d’un livre ne qualifient ni des millions de chunks, ni plusieurs sessions concurrentes, ni la durée d’un backlog de GC, ni les coûts disque des rechecks. Mesurer la capacité du profil livré avant d’en promettre le débit ou la latence. Une preuve Docker de ports libérés ne prétend pas avoir inventorié tous les listeners de l’hôte.

## Revue ciblée du protocole lifecycle gelé

Lecture indépendante sur `invoke-linux-lifecycle.py` SHA `ef1fe8dde00c5e6182d45fa9612cd8606518ea7e4a6a89d033f4d660dd8c2662` et `linux_lifecycle_checks.py` SHA `b592022ed7873a7f9693df9c9f5ea827701bd2178343206988af038a0b3f6606`. Aucun nouveau défaut matériel identifié après les trois durcissements de la première contre-revue.

Le précédent corpus réel, le owner, la configuration et la DLL sont reliés ; les mutations sont limitées au PDF synthétique connu et aux API du namespace possédé ; SQL reste en lecture seule. Le point réinjecté est un point A réellement capturé. Les autres publications et vecteurs sont comparés. L’ACK d’annulation doit être explicite et le terminal canceled ; une fin concurrente reste NON_EXECUTED. Le finally ne dépend plus du maintien du hash PDF pour annuler les jobs admis, mais conserve les gardes d’ownership. Aucun conteneur n’a été lancé par ce relecteur.

Deux nuances restent importantes dans le résultat réel : `observedBeforeCancel` peut être queued ou running, et doit être publié tel quel ; la réinjection d’un point tardif ne prouve pas qu’une requête worker en vol a réellement été annulée. Le code transitoire `reappearance_removed` peut être remplacé avant prélèvement : cela peut provoquer un faux échec borné, jamais un faux PASS d’absence sans sweep.

## Défaut de fixture OCR : preuve et portée

La note `linux-ocr-e2e/deflate-static-analysis-v1.json` conserve la reconstruction pure de l’ancienne fixture : DEFLATE brut sous `/FlateDecode`, sans enveloppe zlib visible ; un lecteur zlib rejette ce flux reconstruit, alors que son lecteur raw l’accepte. La ligne décorative dépassait aussi le canvas (x1846 pour largeur1700). Cette reconstruction n’exécute pas la DLL et ne prouve pas à elle seule la cause unique de l’échec moteur V1 : un renderer permissif peut réparer un flux. Le test ancien ne localisait pas suffisamment son Assert.NotNull.

Le correctif autorisé ne touche que `PdfOcrTextExtractorTests.cs` : ZLibStream, canvas2100×2720, refus du clipping/glyph manquant, deux gardes de fixture, diagnostic reason/exit/timeout/stderr borné et six tokens requis (`pump reset panel batch code xq42`) au lieu du seuil4/10. Le ciblé central `ocr-fixture-correction-v2`, run `b58bc32e7ac043cc852effcd23cfbc23`, confirme60 PASS, zéro échec, un OCR non exécuté, sources stables. Backend EE4E inchangé ; nouvelle test DLL89D81F…99D64. Le smoke Linux V2 reste un gate réel séparé.
